## 1. 需求拆解

用户原始需求 → 技术映射：

| # | 需求原文 | 技术映射 |
|---|---------|---------|
| 1 | 效果库中增加一个频谱效果：催眠 | 新增 `VisualizerTheme` 枚举值 + 新增 `HypnoticFunctionRenderer` + 工厂挂接 |
| 2 | 用动画方式画出各种数学公式的函数图像，带坐标轴 | 预采样点集 + 按时间推进的"部分路径"描线；独立绘制 x/y 轴 + 刻度 + 标签 |
| 3 | 先列举可以动画化的数学公式 | §2 完整清单（53 条，一次性全部实现） |
| 4 | 画完一个，静止一会（3 秒），然后图像溃散 | 四态状态机 `DRAW → HOLD(3000ms) → DISSOLVE → GAP` |
| 5 | 再开始画其他的函数图像 | `GAP` 结束 → 随机取下一个 `FunctionDef` → 重采样 → 回到 `DRAW` |
| 6 | 函数图像随机画，不是按固定顺序 | 洗牌序列 + 相邻不重复约束 + 柔和度加权 |
| 7 | 每幅图像画得不要太快，要能看到绘画效果，描线可以增加到 8 秒 | `DRAW_MS = 8000`；音频变速幅度从 `+0.35` 压到 `+0.15`，把最短描线时间锁在 ≈7.0s（§8.4 / §9） |
| 8 | 切换歌曲不打断绘画过程，动画与歌曲切换无关 | 状态机成员只由 `ctx.nowMs` 推进，**不读 `songId`**；`onEnter` 只在效果被选中时调用一次（§7.3 / §9） |
| 9 | 在屏幕右侧显示函数公式，随动画一起溃散 | 布局改为"绘图区左移 + 右侧公式带"；公式经 `FormulaLayout` 解析为 ≤14 个排版 run（真数学样式）并预计算坐标，`DISSOLVE` 期按 run 碎散，与曲线共用同一 `dissolveProgress`（§8.1 / §11.3 / §11.4） |
| 10 | 阶段不做设定，一次性全部实现 | 取消 P0/P1 分期，53 条函数 + 两个溃散档位 + 公式同步溃散同批交付（§2 / §15） |

设计目标补充（用户未明说但属于"催眠"语义）：节奏必须**慢**。整个周期约 13.9 秒（8000 + 3000 + 2400 + 500），比现有自动切换效果长得多（`RendererSwapper` 交叉淡入 600ms、旧 AUTO_DIRECTOR 8s 驻留），形成明显的"时间变慢"感知。慢的另一面是**长周期内用户会盯着看 13 秒**，所以曲线质量要求比"一瞥而过"的效果高——描线的末端插值（§8.4）和坐标轴刻度语义（§4.4）不能省。

### 2.5 清单设计原则

1. **视觉多样性**：每类至少覆盖"单峰、多峰、振荡、渐近、闭合、开放"六种轮廓，避免连续两张太像。
2. **催眠适配度加权（只影响顺序，不影响出现频率）**：`soft` 越高，越可能排在洗牌序列**前段**（§7.2）。必须说清一个逻辑边界：Fisher-Yates 保证 53 条每条恰好出现一次，所以任何一条的"占比"恒为 1/53 ≈ 1.9%，加权**无法**让柔和曲线出现得更频繁，只能让观众**更早**遇到它们。`soft ≥ 0.95` 的 7 条（A3 / A5 / A13 / A14 / A19 / A20 / D1）优先占据序列前段。
3. **有间断的必须标记**：A6/A10/A11/A16/C7 需要在采样期切段（§4.3），否则描线会出现贯穿屏幕的竖直线，破坏"函数图像"的语义。
4. **显示文本列是"源标记"，渲染时经 `FormulaLayout` 转为完整数学样式**（v2.1，§11）。标记语法：

   | 语法 | 渲染样式 | 示例（源 → 渲染） |
   |------|---------|------------------|
   | `x^{...}` | 嵌套上标（可递归：`e^{-x^2}` → e 的上标是 −x²） | `y = e^{-x^2}` → *y = e⁻ˣ²*（真排版） |
   | `_x{...}` | 下标（本清单暂未用到，解析器预留） | — |
   | `frac{a}{b}` | 真分式（分子 / 横线 / 分母） | `frac{sin(x)}{x}` → sin(x) 处于横线上方 |
   | `√{...}` | 根号字形 + 上横线（vinculum 延伸到内容右缘） | `√{x}` → √x̄ |
   | `x^2`、`sin³t`、`r²` | `^n` 与 Unicode `²`/`³` **等价**，解析器统一转为上标 run，绘制时画普通字形 `2`/`3`（缩小上移），**不直接绘制 U+00B2 等上标字符** | `r²` 与 `r^2` 渲染结果相同 |
   | `·` | 乘点（U+00B7，Roboto/Noto 覆盖稳定，直接绘制） | — |
   | `θ` `φ` `π` | 希腊字母 U+03B8/03C6/03C0，直接绘制（§4.4 已验证覆盖） | — |

   分式规则：`frac` 仅用于源标记中显式写出的位置；`/` 保留为行内斜线（短式更紧凑）。

## 4. 数据模型与函数库（`FunctionLibrary.kt`）

### 4.1 坐标系与函数定义

```kotlin
enum class CurveSpace { CARTESIAN, PARAMETRIC, POLAR }

/** 单条可动画化函数。全部为静态常量，构造期分配一次 */
class FunctionDef(
    val label: String,        // 公式源标记（§2.5 语法），如 "y = e^{-x^2} · cos(12x)"；构造期经 FormulaLayout 解析为 run 并预布局
    val space: CurveSpace,
    val uMin: Float,          // 参数下界
    val uMax: Float,          // 参数上界
    val uGap: Float? = null,  // 可选：第二段起始点（双段定义域）。A10 = 0.3（负段 [-4,-0.3] + 正段 [0.3,4]）；C7 = 3PI/2（[-PI/2,PI/2] + [3PI/2,5PI/2]）。采样器遇到 uGap 即切段，不跨段连线
    val soft: Float,          // 催眠适配度 0.3..1.0，随机加权用
    val tag: String           // 调试/日志用短标识，如 "A19"
)
```

**函数取值不用 lambda，用 `when(id)` 分派**（见 §10.2 R8 考量）。采样器形态：

```kotlin
object FunctionLibrary {
    val ALL: List<FunctionDef>  // 53 条，一次性全部实现

    /** 单点求值。Cartesian: u=x 返回 y；Parametric: 返回 packY(x,y)；Polar: u=θ 返回 r */
    fun eval(def: FunctionDef, u: Float): Float
    fun evalParametric(def: FunctionDef, t: Float, out: FloatArray)  // out[0]=x, out[1]=y
}
```

### 4.2 采样（核心性能决策）

**选定函数时一次性采样到成员 `FloatArray`，之后每帧只做索引插值与绘制。**

| 项 | 规格 |
|----|------|
| 采样点数 N | `HIGH=240`，`MEDIUM=180`，`LOW=120`（按 `ctx.quality` 在 `onEnter` 决定） |
| 缓冲 | `pts: FloatArray(N*2)`（x, y 交替，屏幕像素坐标） |
| 数学→屏幕映射 | 在采样期一次完成：`sx = ox + (u - uMin)/(uMax - uMin) * plotW`，`sy = oy - (y - yMin)/(yMax - yMin) * plotH` |
| y 范围 | **自动**：先扫一遍 `yMin/yMax` 取极值，再上下各留 12% 留白；固定域函数（如 A13 高斯）用显式 `yRange` 覆盖以避免每次重算抖动 |
| 采样时机 | 状态机进入 `DRAW` 的第一帧（此时 `canvasSize` 已就绪），耗时 < 0.1ms。**onEnter 后的首帧同样走此路径**：`phaseStartMs` 哨兵置位时若 `pts` 未采样或 `canvasSize` 已变，先 `resample()` 再绘制——`ensureCapacity` 只保证缓冲容量，不保证内容有效 |
| 画质变化 | `RendererSwapper` 会重建渲染器（§9），`onEnter` 全量重置状态机与缓冲。因此 `ensureCapacity` **不做**新旧缓冲迁移：容量不符直接重建空缓冲，由下一帧 `resample` 重新填充 |
| 零分配保证 | `pts` / `segs` 在 `onEnter` 或首次采样时分配，尺寸变化时重建，**draw 内不分配** |

> 为什么不在每帧求值：每帧 240 次三角函数 + 插值在 TV 中端 SoC 上约 0.3–0.5ms，本身不算贵；但"选定后预采样"让溃散阶段的**逐点扰动**可以复用在同一份点集上，两个阶段共享一份几何数据，内存与结构都更简单。

### 4.3 间断与越界处理（避免画错图）

函数在渐近线/未定义处必须**断笔**，否则描线会出现贯穿坐标系的竖直线。三条规则：

1. **值越界**：`|y| > yLimit`（`yLimit = yRange * 3`）视为无效点，跳过。
2. **相邻跳变**：`|y[i] - y[i-1]| > plotH * 4` 判定为跨越渐近线，在此处开新段。
3. **非法值**：`NaN` / `±Inf`（A10 的 `1/x` 在 x=0、A16 的 `ln(x)` 在 x≤0）→ 该点不入段，开新段。

段信息存到 `segs: IntArray`（每段的起始下标 + 结束下标打包成 `start * 65536 + len`），`segCount` 计数。绘制时对每个段单独 `moveTo` 起笔。

**参数曲线**（B 类）**不需要断笔逻辑**：`t` 连续 → 点连续，闭合曲线在 `t = uMax` 处回到起点。

### 4.4 刻度与标签

坐标轴刻度必须与函数语义匹配，两种刻度表：

| 表 | 触发条件 | x 轴标签 | y 轴标签 |
|----|---------|---------|---------|
| π 刻度 | 笛卡尔类且 `uMax/uMin` 是 π 的整数倍（A1–A6、A21、A23–A25；A22 域为 [-4,4] 非 π 倍，走整数刻度） | `-2π  -π  0  π  2π` | 整数 `-2 -1 0 1 2` |
| 整数刻度 | 其它笛卡尔类 | `-3 -2 -1 0 1 2 3`（自适应步长） | 同上 |
| 无标签 | 参数 / 极坐标类 | 仅画 5×5 网格 + 十字轴，**不打数字**（`x = cos³t, y = sin³t` 这类打数字反而误导） | 同左 |

标签字符串在采样期写入成员 `String[]`（长度 ≤ 8），**不每帧构造字符串**。π 用 `'\u03C0'`（系统字体 Noto Sans CJK 覆盖，minSdk 22 安全）。

## 5. 状态机

### 5.1 四态定义

```kotlin
private enum class Phase { DRAW, HOLD, DISSOLVE, GAP }
```

| 状态 | 时长 | 行为 |
|------|------|------|
| `DRAW` | **8000ms**（用户指定） | 沿采样点从左向右描线，240 点用 8 秒走完 ≈ **30 点/秒**，肉眼可跟随笔画移动；描线头带亮点与短拖尾；坐标轴与右侧公式在起笔前 300ms 内淡入并**全程保持完整** |
| `HOLD` | **3000ms**（用户指定） | 完整图像 + 完整公式静止。允许极轻微的整体呼吸（缩放 1.000→1.006，肉眼几乎不可见），避免"死图"感 |
| `DISSOLVE` | **2400ms** | 图像与公式**同步**溃散（§6 / §11.4）。进度先慢后快（平方缓动） |
| `GAP` | **500ms** | 空场呼吸：坐标轴 alpha 降到 0.15，为新图让位 |

**周期合计 13.9s**（8000 + 3000 + 2400 + 500）。

> 时长全部提为 `companion object` 常量（`DRAW_MS = 8000` / `HOLD_MS = 3000` / `DISSOLVE_MS = 2400` / `GAP_MS = 500`），调参不改状态机逻辑。`HOLD_MS = 3000` 严格对应用户"静止一会（3 秒）"，`DRAW_MS = 8000` 对应用户"描线可以增加到 8 秒"。
>
> **`DRAW_MS` 从 3600 提到 8000 的连带影响**（已逐处同步）：① 音频变速幅度必须同步压低，否则脉冲会把 8s 压缩回 5s，等于没改——见 §8.4 / §9；② 一个周期从 9.5s 变 13.9s，用户连续观看 5 分钟约经历 20 个周期（3 分钟不够验证 53 条不重复），验收 checklist 已相应调整（§13.4）；③ `Path` 部分路径点数上限不变，描线期每帧 draw 成本不随时长变化。

### 5.2 时间基准

沿用 `EcgWaveRenderer.kt:82-86` 的成熟做法，**不依赖帧率**：

```kotlin
val now = ctx.nowMs
if (phaseStartMs == 0L) phaseStartMs = now
val dt = ((now - phaseStartMs) / 1000f).coerceIn(0f, 0.1f)   // 前向推进；倒挂钳制
```

- 前进用**绝对时间差**（`now - phaseStartMs`）算阶段进度，不用累加 `dt`（累加会漂移，TV 掉帧时表现明显）。
- `dt` 只用于粒子/抖动增量与描线累加器，且 `coerceIn(0f, 0.1f)` 防御切后台回来的一次性大跳变。
- **阶段超时保护**：`now - phaseStartMs > phaseDurationMs * 3` 时无条件推进到下一态（应对极端的时钟异常）。推进**必须复用 §5.3 的正常迁移路径**（含 `pickNext` / `resample` / `initDissolve`），只翻 `phase` 标志不走迁移逻辑会卡死在 GAP。
- **DRAW 阶段的超时推进特殊处理**：描线进度是累加器（§8.4），不是绝对时间差。后台长时间返回后，`dt` 被钳制导致累加器远落后于阶段时长；若超时保护直接把 `DRAW` 推到 `HOLD`，会出现"只画了 1% 就静止"的画面。因此 `DRAW → HOLD` 的超时推进**必须先把 `drawAccumulator` 补满到 `DRAW_MS`**（保证完整图像），再进入 `HOLD`。`HOLD` / `DISSOLVE` / `GAP` 的进度是绝对时间差，无此问题。

### 5.3 状态迁移

```
GAP ──选函数+采样──▶ DRAW ──进度≥1──▶ HOLD ──满 3000ms──▶ DISSOLVE ──进度≥1──▶ GAP ─▶ ...
```

迁移发生在 `draw()` 内部（与 `EcgWaveRenderer` 同构），**不引入协程/Timmer**：

1. 迁移后 `phaseStartMs = ctx.nowMs`。
2. `GAP → DRAW` 时：`pickNext()` 取随机函数、`resample()` 采样、`initDissolve()` 重置溃散状态。
3. `HOLD → DISSOLVE` 时：初始化逐点随机扰动参数（`jitterPhase` / `jitterSpeed` 从确定性 RNG 取）。

## 6. 溃散算法

两个实现档位，按 `ctx.quality` 选择，共享同一状态机。

### 6.1 方案 A · 抖动蒸发（`LOW` / `MEDIUM`，默认）

零额外内存，逐点原地扰动 + 选择性跳过 + alpha 衰减：

```
d = dissolveProgress        // 0..1，已做平方缓动（注意：与 §5.2 的 t（毫秒）不同名不同义）
for i in 0 until N:
    p = smoothstep(d)                       // 0..1
    // ① 逐点抖动：相位随 i 错开，幅度随 p 增大
    ox = sin(p * 18 + jitterPhase[i]) * 26 * p
    oy = cos(p * 23 + jitterPhase[i]) * 26 * p
    // ② 蒸发：p 大于"该点的蒸发阈值"时该点消失
    if p > vanishAt[i] continue
    // ③ 整体透明度
    alpha = (1 - p) * 0.95
    drawCircle(color, 3f, pts[i] + (ox, oy), alpha)
```

- `jitterPhase: FloatArray(N)`、`vanishAt: FloatArray(N)`（每个点独立的消失时刻，均匀分布在 0.35~1.0，保证溃散有层次而不是齐刷刷淡出）—— 在 `HOLD → DISSOLVE` 迁移瞬间从确定性 RNG 一次性写入。**`vanishAt` 上限取 1.0 是刻意设计**：部分点不单独蒸发、只随整体 alpha 淡出，让曲线轮廓撑到最后一刻才整体消隐，与公式的"提前散干净"（§11.4 衰减 1.15）形成主次节奏。
- 描线在溃散期改画**离散点**而非连续 `Path`，视觉上就是"图像碎成粒子散开"。
- 成本：≤ 240 次 `drawCircle`，`LOW` 画质 120 次。

### 6.2 方案 B · 粒子化坍缩（`HIGH`）

把点集升格为 240 个粒子，走"先崩解、后下落蒸发"两段：

- 缓冲：`FloatArray(N * 6)`（x, y, vx, vy, life, hue），沿用 `ParticlePool.kt:16` 的布局约定（`STRIDE=6` + swap-remove），但**自建轻量数组，不复用 `ParticlePool` 类**——避免与 E08/E09/E14/E19 的实例竞争，也让本效果保持 `Tier.BASIC`。
- 初速度：沿曲线切线方向 ± 扰动（切线由 `pts[i+1] - pts[i-1]` 计算），保证溃散有方向感而不是球状爆炸。
- 分段节奏：`t < 0.45` 只做抖动与微幅发散（呼应"凝视后突然崩解"）；`t ≥ 0.45` 叠加轻微向下重力 + 阻尼衰减。
- 节拍耦合：`frame.beat == true` 时对该帧所有粒子注入一次向外的速度脉冲（×1.35），把溃散节奏绑到鼓点上。
- 崩溃末尾 20% 用 `BlendMode.Plus` 加一次整体辉光闪烁（alpha 峰值 0.25），模拟"碎裂时的余光"。
- **公式 run 不受档位影响**：方案 B 只替换曲线点的溃散方式（抖动蒸发 → 粒子坍缩），右侧公式的 run 溃散在 `HIGH` 与 `LOW`/`MED` 完全共用 §11.4 的同一套逻辑，不随画质降级。

### 6.3 坐标轴在溃散期的表现

坐标轴**不溃散**，只做降透明度（0.55 → 0.18）+ 线宽轻微收窄。理由：坐标轴是"场景"，函数曲线是"主体"；主体崩解而舞台保留，才有"演出结束"的语义。

## 7. 随机调度（不固定顺序）

### 7.1 洗牌序列 + 顺序指针

```kotlin
// Fisher-Yates，成员字段持有；只在 onEnter 洗一次，切歌/暂停均不重洗
private val order = IntArray(ALL.size)
private var orderPtr = 0
private fun pickNext(): FunctionDef {
    if (orderPtr >= order.size) shuffle()      // 一轮走完 → 重洗
    val idx = order[orderPtr++]
    return ALL[idx]
}
```

**为什么不用 `rng.nextInt(n)` 直取**：短周期内大概率连出相似轮廓（53 条里有 20 条 `soft ≥ 0.9`，其中阻尼振荡、拍频、chirp 这几类形状接近），用户 30 秒内可能看到 3 张"看着差不多"的图，随机感很差。洗牌序列保证**单周期内 53 条全不重复**，跨周期才可能再现。

### 7.2 加权（贴合"催眠"基调）

洗牌目标是"柔和曲线更可能**更早**出现"，但不能牺牲随机性。实现为**三步**：

1. **整体 Fisher-Yates**：对 53 个索引完全洗牌（保证每条恰好出现一次、位置全随机）。
2. **前段 soft 加权重排**：取洗牌结果的前 60%（≈32 条），按 `soft` 与随机扰动的加权和（`score = soft + rng.nextFloat() * 0.25`）降序排；后 40%（≈21 条）**保持 Fisher-Yates 的完全随机序**，只整体拼在前段之后。⚠️ 不要实现成"后 40% 保持偏序"——那会让 `soft` 最低的函数（A18）每个周期都固定排最后，位置可预测，违反"不固定顺序"的本意。
3. **跨周期防重**：洗牌完成后检查 `order[0]` 的 tag 是否等于上一周期 `order[last]` 的 tag（洗牌序列在 `orderPtr` 走完时重洗，跨周期交界处两张图可能相同）。相同则把 `order[0]` 与 `order[1]` 交换。首轮无"上一周期"，跳过此步。

这三步保证：单周期 53 条全不重复（步 1）、周期交界不重复（步 3）、柔和曲线偏向早出现但不死板（步 2）。

### 7.3 随机源与"切歌不打断"

- 用 `kotlin.random.Random(seed)` 成员实例，**构造期取一次，之后永不重取**：`HypnoticFunctionRenderer(seed: Long = System.nanoTime())`——生产路径用默认参数（每次进入效果随机顺序），测试路径注入固定 seed 以断言确定性序列。`onEnter` **不**触碰 `rng`（重进效果会重建渲染器实例，天然换 seed）。
- **不读 `RenderContext.songId`**（`RenderContext.kt:23`）。切歌、暂停、静音、后台拉回前台都**不重洗、不重置状态机**——动画与歌曲播放状态完全解耦，当前图像一定完整走完"描线 → 静止 → 溃散 → 换图"才结束。
- 为什么取消"切歌重洗"：一个周期 13.9 秒，普通歌曲 3~5 分钟会自然经历 13~22 个周期，顺序变化已经充分，不需要靠切歌打散；而切歌重洗会让用户正好看到画面跳变（当前图突然变成另一张），破坏"催眠"的沉浸感——这是本次修订明确去掉的行为。
- **不使用** `VisualizerMath.nextRandom()`：那是全局共享的确定性序列，被 8 个粒子类效果共用，混用会让粒子效果与函数效果互相污染随机相位。
- `order` 数组大小与 `ALL.size`（53）绑定，`onEnter` 时按 `order.size != ALL.size` 重建（防御未来增删函数）。

### 7.4 状态机幂等性（切歌解耦的实现前提）

"动画与歌曲切换无关"不是靠判断"是否正在切歌"实现的，而是靠**根本不读任何歌曲相关字段**：

| 状态机依赖 | 来源 | 是否受切歌影响 |
|-----------|------|---------------|
| 当前阶段 `phase` | 成员变量 | 否 |
| 阶段起点 `phaseStartMs` | `ctx.nowMs`（单调时钟） | 否 |
| 描线累积器 `drawAccumulator` | 成员变量 | 否 |
| 采样点集 `pts` / 段表 `segs` | 成员变量 | 否 |
| 公式 run `runText` / 坐标 `runPos` / 装饰线 `decorLines` | 成员变量（采样期预布局） | 否 |
| 随机序列 `order` / 指针 `orderPtr` | 成员变量 | 否 |
| 色彩 `palette` | `ctx.palette`（封面色） | **是**——切歌换封面色，曲线颜色随之变化，这是预期行为，且**只改颜色不改几何与阶段** |

唯一的例外是 `palette`：切歌后封面色改变，曲线与公式颜色会跟着变。这是"氛围跟随音乐"的合理部分，但必须保证**换色不触发重采样、不重置描线进度**——颜色在每帧绘制时从 `ctx.palette` 实时读取，不缓存到几何缓冲里。

`ctx.nowMs` 是单调时钟（`SystemClock.uptimeMillis` 语义），切歌/暂停不影响其推进，所以阶段进度不会出现"跳回起点"。唯一风险是切后台时长导致 `dt` 一次跳到很大值，已由 §5.2 的 `coerceIn(0f, 0.1f)` 钳制。

## 8. 绘制管线与视觉规格

### 8.1 布局（绘图区左移 + 右侧公式带）

公式在屏幕右侧、随动画同步溃散，因此布局必须给右侧留出独立"公式带"，绘图区相应左移——这是本次修订从"右上角小字标注"改为"右侧公式带"的必要连带调整。

```
┌───────────────────────────────────────────────────────────────────┐
│                          safeAreaPx (≥5%)                         │
│                                                                    │
│  左边距 7%    绘图区 66% w         间隙 9%     公式带 18% w        │
│  ┌───────┐ ┌────────────────────────┐          ┌────────────┐    │
│  │       │ │         y ↑            │          │ y = e^(    │    │
│  │       │ │  ──────── 0 ──────→ x  │          │ -x^2) ·    │    │
│  │       │ │                        │          │ cos(12x)   │    │
│  └───────┘ └────────────────────────┘          └────────────┘    │
│                 中心 = 0.40w                   右对齐 · 垂直居中    │
│                                                y 基线 = h/2        │
└───────────────────────────────────────────────────────────────────┘
```

> 公式断行示意按 §11.2 run 边界规则，不在 run 中间截断。

| 区域 | 规格 |
|------|------|
| 绘图区中心 | `plotCx = w * 0.40`（从屏幕中心左移 10%） |
| 绘图区宽高 | `plotW = w * 0.66`，`plotH = minDim * 0.56` |
| 原点 | `ox = plotCx`，`oy = h / 2` |
| 绘图区右边界 | `ox + plotW/2 = 0.73w` |
| 公式带 | `labelBandW = w * 0.18`，左边界 `w - labelBandW = 0.82w`；与绘图区间距 **9% 屏宽**（1920p 上 ≈ 173px，足够视觉分离） |
| 公式位置 | 右对齐 `x = w - safeAreaPx - 32`，垂直居中基线 `y = h / 2`；最多 3 行，行高 1.35× 字高 |
| 极坐标类 | 直径取 `min(plotW, plotH)`，圆心仍在 `(ox, oy)`，不被公式带挤压变形 |

**为什么 18% 而不是更窄**：最长公式 `x = 16sin³t, y = 16cost-5cos2t-2cos3t-cos4t`（56 字符）在 22sp 下需要约 3 行才能放下，18% 屏宽（1920p ≈ 345px）正好容纳每行 12~14 个字符。再窄就必须缩小字号到 16sp，10-foot 观看距离下不可读。

**为什么公式带不居中放屏中央下方**：屏幕底部有进度条与歌曲信息（左下），中间是主体视觉区；公式放右侧是唯一不与现有 UI 冲突、且能与"从左向右描线"的阅读方向形成呼应的位置（线画到右边，公式在右边）。

### 8.4 描线动画细节

- **进度映射**：`DRAW` 阶段 `progress = clamp(now - phaseStartMs, 0, DRAW_MS) / DRAW_MS`，取整索引 `idx = (progress * (N-1)).toInt()`，前 `idx+1` 个点入 `Path`。
- **末端插值**：`fractional = progress*(N-1) - idx`，末端点用 `VisualizerMath.lerp` 在两采样点间插值，消除描线的步进感（这一步是关键细节，缺失时 120 点会在 1080p 上肉眼可见卡顿）。
- **音频变速**：进度基准改为**可变速度积分**——`DRAW` 阶段用累加器 `drawAccumulator += dt * speed`，`speed = 1.0 + pulse * 0.15`（上限 1.15）。注意 §5.2 的"绝对时间差算阶段进度"结论仍成立：阶段时长下限按 `DRAW_MS / 1.15 ≈ 6.96s` 保证——即使在最强鼓点下描线也不少于 7 秒，尊重"画得慢、看得清"的定位。累加器与 `dt` 钳制的交互（后台返回补满）见 §5.2。
- **起笔节奏**：前 12% 进度用 `easeOutCubic` 缓入（从中心原点起笔时最自然），之后线性。
- **公式同步书写**：右侧公式不是一次性淡入，而是**run 按描线进度分批显现**——第 `k` 个 run 在 `progress ≥ k / R` 时开始淡入（300ms 内到 `alpha 224`），`R` 为 run 数（≤14）。效果是"边画曲线边写公式"，描线头走到哪、公式写到哪，两个动作共享同一时间轴。这也是 8 秒描线时长的体验红利：3600ms 时公式几乎来不及写完，8000ms 下 14 个 run 各有约 570ms 的书写窗口，节奏从容。

### 8.5 `HOLD` 阶段的微动

静止 3 秒必须有极轻微的生命感，否则是"卡住了"。采用**整体呼吸缩放**：

- `scale = 1.0 + 0.006 * sin(holdT * 2π / 3000ms)`，围绕原点缩放采样点（绘制时乘系数）。
- 同时曲线辉光 `alpha` 做 0.14 ↔ 0.22 的缓慢正弦（周期 3000ms，与 HOLD 等长，正好完成一次完整呼吸）。
- 总振幅 0.6%，10-foot 观看距离几乎不可察，但让画面"活着"。
- **公式同步呼吸**：run 的 `alpha` 做 `0.82 ↔ 0.95` 的正弦（同周期 3000ms、**同相位**），位置不位移。与曲线辉光的相位对齐是刻意的——如果公式不动而曲线在动，视觉上会读成两个独立图层，破坏"公式描述这条曲线"的整体感。
- **与音频联动的合成方式**：`HOLD` 期辉光 alpha = `energy 驱动值 × (0.7 + 0.3 · 呼吸因子)`——呼吸作为**调制系数**乘在 §9 的 energy 驱动值上，两条规则不叠加冲突。energy = 0（静音）时呼吸仍保留（系数 0.7~1.0），静音画面同样有生命感。

## 9. 音频联动

**基调：克制**。这是氛围效果，不是节拍可视化。联动只做"氛围增强"，不做"图形变形"。

| 输入 | 输出 | 范围 |
|------|------|------|
| `frame.pulse` | 描线速度倍率 | `1.0 + pulse*0.15`（≤1.15×，描线最短仍 ≈ 7.0s） |
| `frame.energy` | 曲线辉光 alpha / 公式 run 辉光 | 曲线 `0.16 + energy*0.14`（≤0.30）；公式 `0.10 + energy*0.08` |
| `frame.bass` | 曲线主线线宽 | `2.4px * (1 + bass*0.25)`（≤3.0px） |
| `frame.beat` | 溃散期粒子速度脉冲 + 公式 run 横向抖动 | 粒子一次性 ×1.35（方案 B）；run 叠加一次 ±8px 抖动 |
| `frame.treble` | 描线头半径 | `10px * (1 + treble*0.3)` |
| 无信号（`energy < 0.001`） | **全静态节奏** | 速度=1.0、辉光=0.16、线宽=2.4px、公式按 `DISSOLVE` 时间轴正常碎散 |

**关键差异点（与 `EcgWaveRenderer` 对比）**：`EcgWaveRenderer` 的图形内容就是音频波形，静音即无图；本效果的图形内容是**数学定义**的，`AudioFrame` 只影响氛围参数。因此：

- **静音 / 暂停**：曲线继续按 8s 描线，辉光与线宽落到静态基线值，效果完整可看。
- **切歌**：`onEnter` **不会**被重新调用（`RendererSwapper` 只在主题或画质变化时重建渲染器），状态机成员全部保留，当前图像继续画完。**唯一变化是 `ctx.palette` 换色**（新封面色），只改颜色不改几何、不重置进度——见 §7.4 的状态依赖表。
- **后台拉回前台**：`ctx.nowMs` 是单调时钟，阶段进度可能一次跳很大值，`dt` 被 `coerceIn(0f, 0.1f)` 钳制，最坏情况是阶段被超时保护（§5.2）直接推到下一态，**不会跳回起点、不会卡死**。

这三点是"动画与歌曲切换无关"的完整实现保证：不是"检测到切歌后特殊处理"，而是**结构上没有任何代码路径会读取歌曲状态并影响阶段推进**。

## 11. 公式标注渲染

### 11.1 方案：`FormulaLayout` 自绘数学排版（真公式样式）

v2.1 明确：公式必须渲染**完整数学样式**——嵌套上标、真分式、根号横线，不是 `e^(-x^2)` 的 ASCII 退化写法。实现为自绘 mini 排版器（≈200 行，零外部依赖，minSdk 22 安全）：

**三段式管线**：

1. **解析**（构造期）：`label` 源标记 → `runs: List<FormulaRun>`。每个 run = `(text, level, role)`：`level 0` 基线、`level +1` 上标、`-1` 下标；`role` 区分普通文本 / 分式分子 / 分式分母 / 分式线 / 根号线。
2. **预布局**（采样期一次）：对每个 run `measureText` → 写入 `runPos: FloatArray(R*4)`（x, y 基线, textSize, 宽）与 `decorLines: FloatArray(L*4)`（分式横线 / 根号上横线的 x1,y1,x2,y2）。分式：分子分母以分数线为中心，run 高 ≈ 2.1em；根号：`√` 字形绘制后，从其顶部横杠延伸一条线到内容右缘。**每帧零测量、零解析**。
3. **绘制**（每帧）：`nativeCanvas.drawRun(runPos[i])` + `drawLine(decorLines[j])`，全部复用 2 个 `Paint`。

```kotlin
// 成员，构造期创建一次
private val labelPaint = android.graphics.Paint().apply {
    isAntiAlias = true
    textSize = 34f                 // 约 22sp @2.0 density，1080p 清晰
    color = 0xFFFFFFFF.toInt()
    textAlign = android.graphics.Paint.Align.RIGHT
    alpha = 224                     // 0.88
}
private val decorPaint = android.graphics.Paint().apply {  // 分式线/根号线
    isAntiAlias = true; strokeWidth = 2f; color = 0xFFFFFFFF.toInt()
}
private val tickPaint = android.graphics.Paint().apply { textSize = 22f; ... }
```

**为什么不选其它路径**：

| 方案 | 结论 |
|------|------|
| Unicode 上标字符（`e⁻ˣ²`） | ❌ U+2070 区字体覆盖差（国产 ROM 常缺），且**无法嵌套**（上标里还有上标），A19 招牌曲线直接不可行 |
| Compose `AnnotatedString` + `TextMeasurer` | ❌ 分式/根号没有 span 语义；`TextMeasurer` 每帧构造 `TextLayoutResult` 违反零分配红线 |
| 静态预渲染 Bitmap | ❌ 溃散需要 run 级独立坐标与 alpha，Bitmap 只能整体动；且 GAP 换公式需重建 |
| **Canvas run 排版（选定）** | ✅ 预布局后每帧只有 `drawText`/`drawLine`，与词块溃散机制天然兼容（run 就是更细的"词块"） |

**字体覆盖收益**：解析层把 `^2`/`²` 统一转成上标 run，绘制时画**普通字形** `2`（缩小 0.65×、基线上移 0.42em）——完全不绘制 U+00B2/U+2070 区字符，把上标字体的覆盖风险降为零。希腊字母 `θ`/`φ`/`π`（U+03B8/03C6/03C0）在 Roboto/Noto Sans Greek 覆盖稳定，直接绘制（§4.4 已验证）。

### 11.2 解析规则与溢出策略

- 解析语法见 §2.5 的标记表。解析器为纯函数 `parseFormula(label): List<FormulaRun>`，纯 JVM 可单测；`frac{}/√{}` 的花括号必须配对，不配对时降级为**字面文本绘制**（把源标记原样画出）并打日志——清单错误在 §13.1 单测拦截，运行时不崩溃。
- `²`/`³`/`^2`/`^3` 统一解析为上标 run（绘制普通字形），`·`（U+00B7）与希腊字母直接作为基线 run。
- **run 数上限 `R = 14`**：53 条中最长 label（B5，56 字符）解析后 ≈ 12 个 run；嵌套上标 A19 ≈ 10 个。上限 14 覆盖全部条目，超限时按相邻合并收敛。
- **断行**：公式带宽度 `labelBandW = w * 0.18`，**从头往后**贪心填行——行序严格保持 label 的阅读顺序（第一行是 label 开头），整体靠 `Align.RIGHT` 右对齐；最多 **3 行**。⚠️ 不能"从末尾往前填行"，那会把 label 尾段排到第一行、颠倒阅读顺序。断行点只落在 **level 0 的 run 边界**（上标/分式体不允许与宿主 run 分行）；含分式的行高按 2.1em 计。判断依据是 `measureText` 累加，采样期一次性完成。
- **缩字号兜底**：若 3 行仍装不下，`textSize` 按宽度预算反算，下限 `26f`（≈16sp）。再装不下说明 label 写太长，属于清单问题——§13.1 的 `all labels fit the layout width budget` 单测会拦下来。
- run 坐标**预计算**：解析与断行完成后，把每个 run 的基线坐标写入 `runPos: FloatArray(R*4)`，装饰线写入 `decorLines: FloatArray(L*4)`。之后每帧只做 `drawText` + `drawLine`，**不每帧 measureText / parseFormula**。

### 11.3 位置与层级（屏幕右侧）

- **位置**：右对齐基线 `x = w - safeAreaPx - 32`，垂直居中锚点 `y = h / 2`；多行时以锚点为中心上下排布，行高 `textSize * 1.35`（含分式的行按 `2.1em` 计）。`Align.RIGHT` 保证所有行右边缘对齐成一条竖线，公式带视觉上是一个整块。
- **边界**：`x` 必须钳制到 `[w * 0.82, w - safeAreaPx]` 区间内（§8.1 的 9% 间隙不可侵入）。超宽屏测试时重点核这里（TV 横屏锁定，无竖屏场景）。
- **与歌词/信息的避让**：舞台顶栏是歌词行、左下是歌曲信息（`VisualizerStage.kt:308` 附近），屏幕右侧中垂线区域是空的，公式带放这里**不与任何现有 UI 重叠**。
- **层级**：公式在曲线**之上**（绘制顺序第 9 层），但 alpha 上限 0.88 < 曲线主线 0.95，视觉主次仍是曲线。
- **入场**：`DRAW` 期 run 按描线进度分批淡入（§8.4"公式同步书写"），不是整段一次性出现。

### 11.4 公式溃散动画（与曲线同步）

`DISSOLVE` 阶段公式**不是整体淡出**，而是按排版 run 碎散，与曲线的逐点蒸发共享同一条时间轴——这是"随动画一起溃散"的核心实现。run 比 v2.0 的词块更细（上标、分式分子/分母是独立 run），碎散后视觉上连公式**结构**都在崩解（上标飞离宿主、分式线断开），与"数学公式溃散"的语义更贴合。

**共享时间轴**：曲线用 `dissolveProgress`（0..1，平方缓动，§6.1），公式直接用同一个值，不做二次映射。两边进度严格对齐，观众看到的是"曲线散到哪、公式散到哪"的整体崩解，而不是两个各自动画。

```
d = dissolveProgress                     // 与 §6.1 同一个变量
for k in 0 until R:                      // R = run 数，≤ 14
    p = d                                // run 与曲线点共用同一缓动曲线
    if p > runVanishAt[k] continue       // ① 该 run 已蒸发
    // ② 逐 run 抖动：相位随 k 错开，幅度随 p 增大（与曲线点的 26px 幅度同量级）
    ox = sin(p * 19 + runJitter[k]) * 22 * p
    oy = cos(p * 21 + runJitter[k]) * 14 * p
    // ③ 透明度：比曲线点衰减略快一点，公式先散干净（它是"注解"，主体散了它就该走）
    a = (1 - p * 1.15f).coerceAtLeast(0f) * 224
    drawText(runText[k], runPos[k*4], runPos[k*4+1] + oy * 0.65f * runLevel[k], paint.alpha = a)
for j in 0 until L:                      // 装饰线（分式线/根号线）
    if p > runVanishAt[decorHost[j]] continue
    drawLine(decorLines[j*4] + ox, decorLines[j*4+1] + oy, ..., decorPaint)
```

> 装饰线跟随**宿主 run**（分式线宿主 = 分子 run，根号线宿主 = 根号内首 run）：宿主蒸发则线随之消失，宿主抖动则线随之平移——溃散时"分式横线跟着分子飞走"，视觉一致性由绑定关系保证。

| 项 | 规格 |
|----|------|
| 抖动幅度 | 横向 22px、纵向 14px（小于曲线的 26px，避免公式飞太远显得失控）；上标 run 额外叠加 `×(1 + 0.3·p)` 的纵向漂移，模拟"轻的上标飞得更高" |
| 蒸发阈值 `runVanishAt[k]` | 均匀分布在 `0.30~0.85`，在 `HOLD → DISSOLVE` 迁移瞬间从同一 `rng` 一次性写入（与曲线的 `vanishAt` 同源，保证相位一致）。⚠️ 上限不能取 0.95：alpha 衰减系数 1.15 使公式在 p ≥ 0.87 就已 alpha = 0，超过 0.85 的阈值永远不会触发"消失"，等效于纯淡出，失去碎散语义 |
| 衰减系数 | `1.15`（比曲线点的 `1.0` 快 15%） |
| 描边/阴影 | 溃散期公式**不加**辉光层，只有本色 + alpha，避免 14 run + 4 线 × 辉光的额外开销 |
| `DISSOLVE` 结束后 | 公式与曲线一起在 `GAP` 期消失（alpha = 0），不残留 |

**为什么 run 级而不是逐字符**：56 字符逐字绘制 = 56 次 `drawText`/帧，hwui 每次调用都要走文本光栅化与字体查找，实测同字号下逐字比整块贵约 4~5 倍（详见 §10.2 ⑭）。run（2~8 字符）已经是视觉上可感知的"碎片"粒度，10-foot 距离下与逐字无异，且保留了数学结构语义（上标/分式独立崩解）。

**为什么不是整体淡出**：整体淡出读起来是"图层消失"，而 run 碎散读起来是"图像崩解"——后者与曲线的粒子蒸发是同一语义，观众才会把公式理解为这张图的一部分。这是本次修订明确的效果要求。

```kotlin
 * E25 `HYPNOTIC_FUNCTION` — 催眠 · 数学函数图像动画
 *
 * 三段式：缓慢描线（8.0s）→ 静止凝视（3.0s）→ 溃散蒸发（2.4s）→ 空场（0.5s）→ 随机换函数。

    override val theme = VisualizerTheme.HYPNOTIC_FUNCTION

    private var particleBuf: FloatArray? = null  // 方案 B 粒子 N*6，仅 HIGH 分配（§6.2）
    private var runText: Array<String> = arrayOf("")       // 公式排版 run（§11.1/§11.2）
    private var runPos = FloatArray(0)           // run 坐标 R*4（x, 基线y, textSize, 宽），采样期预布局
    private var decorLines = FloatArray(0)       // 分式线/根号线 L*4，宿主绑定见 §11.4
    private var runVanishAt = FloatArray(0)      // run 蒸发阈值 ∈ [0.30, 0.85]
    private var runJitter = FloatArray(0)        // run 抖动相位
    private val curvePath = Path()
    private val gridPath = Path()
    private val axisPath = Path()
    private val tickPath = Path()
    private val labelPaint = android.graphics.Paint()...
    private val tickPaint = android.graphics.Paint()...
    private var tickLabels = arrayOf("")         // 采样期预生成
    private var label = "y = sin(x)"

    // ── 状态机 ──

    private var phaseStartMs = 0L
    private var drawAccumulator = 0f
    // seed 构造期注入（§7.3）：生命周期 = 渲染器实例，onEnter/切歌均不重置
    private val rng = Random(seed)
    private val library = FunctionLibrary.ALL
    private val order = IntArray(library.size)
    private var orderPtr = 0

    override fun onEnter(ctx: RenderContext) {
        phase = Phase.DRAW
        phaseStartMs = 0L
        drawAccumulator = 0f
        ensureCapacity(ctx.quality)
        shuffle()
    }

    override fun DrawScope.draw(frame: AudioFrame, ctx: RenderContext) {
        val w = size.width; val h = size.height
        if (w < 2f || h < 2f) return
        ensureCapacity(ctx.quality)
        val now = ctx.nowMs
        if (phaseStartMs == 0L) phaseStartMs = now
        val dt = ((now - phaseStartMs) / 1000f).coerceIn(0f, 0.1f)
        val t = ((now - phaseStartMs).toFloat()).coerceAtLeast(0f)

        when (phase) {
            Phase.DRAW      -> drawStroke(frame, ctx, w, h, t, dt)
            Phase.HOLD      -> drawStill(frame, ctx, w, h, t)
            Phase.DISSOLVE  -> drawDissolve(frame, ctx, w, h, t, dt)
            Phase.GAP       -> drawGap(frame, ctx, w, h, t)
        }

        drawAxes(frame, ctx, w, h)          // 图层 1-3（在所有阶段绘制，GAP 期降 alpha）
        drawTickLabels(w, h)                // 图层 8
        drawFormulaLabel(w, h, ctx, frame)  // 图层 9

        advancePhase(now, dt, ctx, w, h)    // 状态迁移（GAP→DRAW 时 pickNext + resample）
    }
}
```

```kotlin
    }

        "A13" -> exp(-x * x)
        "A19" -> exp(-x * x) * cos(12f * x)
        // ...
    }
    fun evalParametric(def: FunctionDef, t: Float, out: FloatArray) { ... }
    fun evalPolar(def: FunctionDef, theta: Float): Float = ...
}
```

**注意**：`A3` 的 `x == 0f` 精确比较在均匀采样下**不会命中**（`-8π + i·Δ` 一般不等于 0）。对策是判 `abs(x) < Δ * 0.25`，`Δ = (uMax - uMin) / N`，在采样器里传入。同理 A10/A16 的域边界由 `FunctionDef` 的双段定义域表达（`uMin/uMax` + 可选 `uGap` 参数，采样器遇到 `uGap` 直接切段）。

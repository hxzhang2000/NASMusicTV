总体评价：代码质量在同类 TV 音乐播放器项目中属上乘——注释与修复纪要详实、大量历史坑有根因沉淀与测试护栏、OkHttp 资源关闭纪律整体极好、下载完整性与文件名清洗做得扎实。剩余问题高度集中在三类模式：① 异步回调完成时未对"世界已变化"做一致性校验（resolve→replay 竞态、旧队列快照回滚、乱序结果覆盖）；② 手动 DI 体系下的生命周期清理缺口（子 ViewModel 无 onCleared、回调注册未注销）；③ 组合期/主线程的磁盘 IO 与重复计算（低端电视盒子上直接表现为掉帧与 ANR）。

交叉优点（值得保持）

  • OkHttp Response 关闭纪律整体极佳：九个子系统逐路径核对（body==null / 非 2xx 提前 return / 解析异常），唯一真实泄漏点是 HqSeparationOrchestrator 一处——在 4 万行级别的手写 OkHttp 代码里属罕见的好纪律。
  • 日志脱敏成体系：UrlSanitizer 统一脱敏 t/s/u/p/api_key/token；登录失败不落响应体、重认证只记世代号、BackendAuthHeaders 只记 host。
  • 历史根因沉淀为 KDoc + 纯函数护栏：MoleculeRenderer §10.176、PhotoTransitionClock 时钟语义、MoleculeMotionTest、MediaSessionAccessPolicy 单测——知识传承机制在同规模项目里突出。
  • 下载完整性扎实：Content-Length 比对、.part + 同分区原子 rename、崩溃恢复按命名规则反推孤儿文件、失败统一清理半成品。
  • 文件名清洗与路径安全：sanitize 覆盖非法字符/控制符/80 字符截断；下载侧无路径遍历入口。
  • 凭据治理：服务器密码/天气 Key/百度 token 均 AES-GCM，备份导出排除敏感字段，normalizeEndpointUrl 双路径生效。
  • 本地 HTTP 服务防御成体系：5 个 NanoHTTPD 全部接入 token 鉴权、定长分块读取 + 硬上限、MultipartBoundaryStreamer 用 KMP 前缀函数处理自重叠边界。
  • 焦点与 BACK 体系一致：FocusableSurface 统一收口（isTVDevice 按 Context 缓存规避 143 处组合期 IPC）、requestFocus 全部 runCatching 兜底、破坏性操作默认焦点落取消键。
  • 性能数据流意识强：progress/duration 严格局部订阅、曲库 pager 只在 draw 相位读取 fraction、每秒重组被限制在叶子组件。
  • Room 使用规范：DAO 全 suspend、仓库层统一 IO、批量事务化、分批删除规避 SQLite 变量上限、LIKE 通配符转义。
  • 可中断扫描/分页防护：FaceScanManager 分片 + yield + isActive、百度分页游标停滞保护、Range 请求只接受 206 防 OOM。

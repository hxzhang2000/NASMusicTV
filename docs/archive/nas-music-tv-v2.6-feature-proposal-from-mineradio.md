# 功能移植方案：从 Mineradio 到 NASMusicTV v2.6

> 版本：1.7.0  
> 日期：2026-07-02  
> 作者：Hermes Agent  
> 状态：草案 / 待评审

---

## 1. 背景与目标

**Mineradio**（XxHuberrr）是一款 Windows Electron 桌面沉浸式音乐播放器，拥有丰富的视觉系统、天气电台、多平台网络音乐接入等特色功能。  
**NASMusicTV** 是一款 Android TV 音乐播放器，基于 Jetpack Compose，支持 Jellyfin/Navidrome 后端。

本方案分析 Mineradio 中可移植到 NASMusicTV 的功能特性，按优先级、可行性、实现难度排期，并为每项功能提供界面设计（TV D-Pad 适配）、用户操作逻辑说明，以及**是否依赖外部账户登录**的可行性评估。

---

## 2. 相关依赖说明

### 2.1 网络音乐接口现状

NASMusicTV 的**网络音乐功能全部基于 Meting API**（`MetingApiService.kt`），这是一个聚合多音乐平台（网易云/QQ/酷狗等）搜索结果的公开 API，**无需任何登录即可使用**。已提供的能力：

| 能力 | 接口 | 状态 |
|------|------|------|
| 搜索歌曲 | `search(keyword)` | ✅ 已有（含多端点 fallback） |
| 获取播放 URL | `resolvePlayUrl(song)` | ✅ 已有 |
| 获取歌词 | `resolveLyrics(song)` | ✅ 已有 |
| 获取封面 URL | `resolveCoverUrl(song)` / `searchCoverUrl()` | ✅ 已有 |
| 获取公开歌单 | `getPlaylist(playlistId)` | ✅ 已有（v2.2.0 新增） |

Meting API 是公开的聚合代理，不需要用户登录任何音乐平台账户。所有方案中的网络音乐功能均基于此接口实现。

### 2.2 无需登录的关键判断

| 登录需求 | 是否需要 |
|---------|---------|
| QQ 音乐/网易云账户登录 | ❌ 不需要 |
| Jellyfin/Navidrome 账户 | ✅ 已有（App 必要功能） |
| Open-Meteo 天气 API Key | ❌ 不需要（免费公开 API） |
| IP 定位服务 | ❌ 不需要（免费公开 API） |

## 3. 整体导航结构

### 3.1 一级 Tab 结构

新增**网络音乐**顶级 Tab（`Screen.Network`），与现有 Tab 并列：

```
┌─────────────────────────────────────────────────────────────────┐
│ ♪  [正在播放]  [本地曲库]  [播放队列]  [网络音乐]  [服务器]  [设置] │  ← 一级 Tab
└─────────────────────────────────────────────────────────────────┘
```

- **正在播放**（`♪` icon）：播放器画面（全屏沉浸模式）
- **本地曲库**（`Screen.Library`）：专辑/歌手/歌曲/流派/年代/收藏/最近播放（内部子 Tab）
- **播放队列**（`Screen.Queue`）：当前播放列表
- **网络音乐**（`Screen.Network`，**新增**）：发现页、天气电台、热门榜单、网络搜索 四大子 Tab
- **服务器**（`Screen.ServerConnect`）：Jellyfin/Navidrome 连接配置
- **设置**（`Screen.Settings`）：应用设置

> 设计说明：将"网络音乐"提升为一级 Tab，是因为越来越多的用户同时使用 NAS 本
> 地曲库和网络音乐服务，两者层级的扁平化能让用户通过 D-Pad 快速切换，无
> 需层层进入菜单。

### 3.2 网络音乐 Tab 内部结构

进入网络音乐 Tab 后，界面分为两层：**子 Tab 栏（左对齐）**与**音乐来源选择器（右对齐，按钮组）**同行。

```
┌─────────────────────────────────────────────────────────────────┐
│ ♪  [正在播放]  [本地曲库]  [播放队列]  [网络音乐]  [服务器]  [设置] │  ← 一级 Tab
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────┬──────┬──────┬──────┐   [网易云] [QQ音乐] [酷狗] [酷我] [咪咕]│  ← 同一行
│  │ 发现  │ 天气  │ 榜单  │ 搜索  │    ↑ 选中状态（Primary 高亮）       │     左:子Tab | 右:来源按钮
│  └──────┴──────┴──────┴──────┘                                 │
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │                                                         │    │
│  │              子 Tab 内容区域                             │    │
│  │  （随子 Tab 切换而变化）                                  │    │
│  │                                                         │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

- **子 Tab 栏**与**音乐来源选择器**在同一行，子 Tab 左对齐，来源选择器右对齐
  - 来源选择器采用**按钮组**形式（与歌词来源选择器 `SourceTag` 风格一致）
  - 5 个来源按钮：网易云、QQ音乐、酷狗、酷我、咪咕（由 Meting API 的 server 参数决定）
  - 当前选中的来源按钮以 Primary 颜色高亮（与 `SourceTag` 的 `selected` 状态一致）
  - 切换来源后，下方所有子 Tab 的内容自动以新来源刷新
  - 不支持的音乐来源按钮显示为灰色禁用状态

### 3.3 子 Tab 功能一览

| 子 Tab | 功能 | 数据来源 |
|--------|------|---------|
| **发现** | 天气卡片、热门推荐、私人电台、继续听、我的歌单等功能聚合页 | Open-Meteo + Meting API `search`/`getPlaylist` |
| **天气** | 天气电台独立页面：天气详情、mood 显示、电台播放、换一换 | Open-Meteo + Meting API `search` |
| **榜单** | 当前来源音乐平台的热门歌单/排行榜 | Meting API `getPlaylist(预置公开歌单ID)` |
| **搜索** | 网络歌曲搜索、播放（当前网络音乐功能） | Meting API `search`/`resolvePlayUrl` |

### 5.2 D-Pad 导航规则

```
一级 Tab 行：D-Pad ← → 切换
     │
     ▼
子 Tab 栏 → 右端到头 → 音乐来源按钮组（同一行内）
├─ D-Pad ← → 在子 Tab 之间切换
├─ 焦点到达子 Tab 最右端后继续右移 → 进入音乐来源按钮组
├─ 来源按钮组中 ← → 切换当前选中的来源（按钮 Primary 高亮随之移动）
├─ 按 OK 确认切换（或左右移动时立即生效）
└─ 按钮组中继续右移 → 折返回子 Tab 第一个
     │
     ▼
子 Tab 内容区域：垂直滚动（↑ ↓ 在内容行之间移动）
                    │
                    ▼
              内容行内：横向滚动（← → 在卡片/歌曲之间移动）
```

- 按**返回键**：从子 Tab 内容 → 子 Tab 栏/来源按钮组 → 一级 Tab 行 → 退出网络音乐区
- 子 Tab 栏与来源按钮组在同一焦点行内，左← →右横向自然过渡，无需额外的上下跳转

### 5.3 音乐来源切换的影响

切换音乐来源时，所有子 Tab 的行为：

| 子 Tab | 来源切换的影响 |
|--------|--------------|
| 发现 | 热门推荐的歌单来源变化（如从网易云榜单变为 QQ 音乐榜单） |
| 天气 | mood 搜索来源变化，搜索结果使用新来源 API |
| 榜单 | 歌单 ID 列表切换到当前来源对应的热门歌单 |
| 搜索 | 搜索结果的来源变化 |

实现方式：
- Meting API 已有 `server` 参数（`netease` / `qq` / `kugou` / `kuwo` / `migu`）
- `MetingApiService.DEFAULT_SERVER` 改为运行时动态读取 `AppPreferences` 中的来源配置
- 子 Tab 内容加载时统一读取当前来源值

### 6.1 P0 — 发现子 Tab（聚合页）

**功能说明**：聚合天气电台入口、热门推荐、私人电台、继续听、我的歌单等功能模块，是用户进入网络音乐区域的第一屏。

**📋 登录依赖评估**：⚠️ **部分需适应**

| 模块 | 实现方式 | 需要登录？ |

**关于"每日推荐"的说明**：
Mineradio 的"每日推荐"依赖网易云登录后的 `/recommend/songs` API，NASMusicTV 无法直接使用。但 Meting API 的 `type=playlist` 端点可以获取**公开歌单**（如网易云飙升榜、热歌榜、新歌榜等）。因此方案中改为 **"热门推荐"**，使用预置的公开热门歌单 ID 列表，按日轮换。

```text
  ├─ 天气子 Tab：mood 搜索使用新来源
  ├─ 榜单子 Tab：歌单列表切换到新来源
  └─ 搜索子 Tab：后续搜索使用新来源（当前搜索不清空）
```

#### 搜索子 Tab 的 UI 搬移说明

当前网络歌曲搜索功能存在于 `NowPlayingScreen` 或 `MainViewModel.searchNetworkSongs` 中。阶段一将其移入 `SearchSubTab`：

```
搬移前：
  LibraryScreen / NowPlaying → 搜索输入 → MainViewModel.searchNetworkSongs()
                                                                   ↓
                                                          MetingApiService.search()

搬移后：
  LibraryScreen → 网络音乐 Tab → SearchSubTab  → MainViewModel.searchNetworkSongs()
                                                              ↓
                                                     MetingApiService.search()
```

#### 架构要点

1. **容器化管理**：`NetworkMusicContainer` 负责来源选择器和子 Tab 导航，子 Tab 内容由 `when(currentSubTab)` 分发到各自 Composable。
2. **来源状态提升**：`MainViewModel` 持有 `currentMusicSource`，子 Tab 通过 ViewModel 读取，来源切换时自动触发数据刷新。
3. **Meting API 改造**：`server` 参数从编译期常量改为运行时读取 `AppPreferences`。
4. **现有功能零重构**：搜索子 Tab 是现有搜索功能的 UI 搬移，不修改业务逻辑。
5. **D-Pad 优化**：一级 Tab → 子 Tab/来源选择器同一行 → 内容区的三层焦点链，子 Tab 栏和来源选择器在同一行横向自然过渡，无需额外的上下跳转。

## 11. MetingApiService 改造方案

当前 `MetingApiService.DEFAULT_SERVER = "netease"` 是编译期常量。为支持运行时来源切换，需要改造：

```kotlin
class MetingApiService(
    private val baseUrlProvider: () -> String,
    private val serverProvider: () -> String    // 新增：运行时获取当前 server
) : NetworkMusicService {

    // 请求时动态读取 server 参数
    private fun searchUrl(keyword: String): String {
        val server = serverProvider()
        return "$baseUrl?server=$server&type=search&id=${URLEncoder.encode(keyword, "UTF-8")}"
    }

    // 同理改造 resolvePlayUrl / resolveLyrics / getPlaylist
}
```

`serverProvider` 在 `NasMusicApp.onCreate()` 中注入：

```kotlin
val metingService = MetingApiService(
    baseUrlProvider = { prefs.metingApiBaseUrl },
    serverProvider = { prefs.musicSource }  // 读取用户选择的来源
)
```

## 12. Android TV 界面设计总则

NASMusicTV 运行在 Android TV 平台，UI 设计必须遵循以下 TV 专属约束：

| 约束 | 说明 | 设计影响 |
|------|------|---------|
| **D-Pad 导航** | 无触摸屏，仅方向键 + OK + 返回 | 所有界面元素必须可聚焦，焦点框清晰可见 |
| **横向为主** | TV 通常横向滚动优于纵向 | 歌曲列表/推荐列表采用 LazyRow |
| **高对比度** | 客厅观看距离远，字体需大 | 歌词最小 18sp，卡片文字 14sp+ |
| **焦点框** | 当前聚焦项需要有显眼边框或缩放 | Compose 的 `Modifier.focusable()` + `focusGroup()` |
| **操作深度** | 尽量减少 D-Pad 点击次数 | 首页直接展示核心功能，不隐藏于菜单 |
| **信息密度** | 不要过于密集，留白充足 | 卡片间距 16dp+，每行 4~6 个卡片 |
| **层极回退** | 多级 Tab 嵌套时返回路径清晰 | 返回键按 内容→子Tab→来源→一级Tab 逐级回退 |

二P1 发现 · 5 条

建议在下一个功能迭代前优先处理；前四条合计不超过一天工作量。

P1-15 个内嵌 HTTP server 全部无鉴权且绑定 0.0.0.0 —— 备份恢复接口可被同网段任意设备调用

位置 RemoteControlServer(18082) · BackupTransferServer(18081) · LocalInputServer(18080) · ModelTransferServer(18083) · PlaylistUploadServer(18084)，均为 NanoHTTPD(port) 通配绑定；代码注释自证「服务器绑定 0.0.0.0」（P1-8 只修了 URI scheme 白名单）。

最重的后果：同一 WiFi 的任意设备可「上传自制备份 → POST /api/restore」远程整体覆盖 / 清空用户全部数据（歌单 / 收藏 / 播放记录）；另可完全遥控播放、经 /api/queue 枚举曲库、向打开中的输入框静默注入文本、覆盖模型文件。威胁模型虽是家庭 LAN，但「静默重置数据」超出项目「有意支持 cleartext」的既定范畴。

修复：启动时生成一次性 token 拼进二维码（http://ip:port/?t=xxx），各 server 的 serve() 头部校验 query/cookie，约 5 行/server；至少先给 BackupTransferServer（数据破坏面）加上。

P1-2SubsonicAdapter.getLyrics 协议参数用错 —— 通用 Subsonic 服务器歌词恒空

位置 backend/impl/SubsonicAdapter.kt · 传 getLyrics?id=$songId；Subsonic API 的该端点参数是 artist + title，服务端忽略多余的 id，因缺参返回空歌词。同仓 NavidromeAdapter 已示范正确两段式（getSong 取元数据 → getLyrics&artist=&title=）。

修复：照抄 Navidrome 两段式，或把实现下沉 SubsonicRestClient 共用。

P1-3NavidromeAdapter 未实现 getYears() —— 「年代」维度恒为空

位置 BackendAdapter.getYears() 默认 emptyList()，MainViewModel:1284 直接消费。getYears 的 override 只有 Jellyfin 与 Subsonic，官方明确支持的 Navidrome 走默认值，用户侧无任何提示。Subsonic 已示范「分页拉歌提取年份」做法。

修复：给 NavidromeAdapter 补 getYears()（与 Subsonic 实现下沉共用）。

P1-4Navidrome 歌单歌曲的 albumId 被写成 playlistId

位置 NavidromeAdapter.getPlaylistSongs()：albumId = playlistId，条目自身的 albumId 字段被丢弃。后果：从歌单跳专辑详情、按专辑找封面的兜底链路全部错位（请求的是歌单的 coverArt，404）。同构的 SubsonicAdapter 实现是对的——属移植走样。

修复：改 albumId = obj.get("albumId")?.asString ?: ""。

P1-5下载档位参数泄漏到非 Meting 源 —— NAS FLAC 被存成 .mp3

位置 DownloadPathBuilder.extOf()（非 AUTO 档一律 return "mp3"）+ baseNameWithQuality()（HIGH 加 " (320)"）；触发链 AutoDownloadController → resolveDetailed（非 Meting 源 actualQuality=请求档）→ singleAttempt。downloadKeyOf 已正确忽略档位，extOf / baseNameWithQuality 没有同样忽略。

全局默认档位=320 时，一首 NAS FLAC 被存为 01 - xxx (320).mp3——内容仍是 FLAC 字节流：媒体扫描可能拒识、jaudiotagger 按容器解析失败（内嵌必败走旁路）、文件名档位后缀是假的。百度网盘 / jamendo 同理。

修复：extOf / baseNameWithQuality 与 downloadKeyOf 同口径——非 Meting 源一律按 AUTO 处理（不猜 mp3，走 URL/path 推断）。

三P2 发现 · 21 条（按主题归组）

每条的位置、代码证据与修复建议见对应模块详单；此处按主题归组给出索引。

主题 A · 同一修复未同步到所有同类点（7 条）最典型的债：修复注记在某个文件里写得很清楚，同类位置没有跟进。
  1. ID3「256KB 固定窗口」全仓 4 处，仅 BaiduCoverProvider 实现了 M5 动态补读：BaiduLyricsProvider（w04）、LocalLyricsProvider 两处（w07）、EmbeddedCoverExtractor（w03）未同步 → 大封面 / 大歌词帧静默失败回退网络错配。建议：抽 readId3HeaderSmart(file) 公共函数统一替换。
  2. 缓存落盘非原子：CoverUrlPersistentCache 已修 tmp+rename，MvPersistentCache（w04）与 LyricsPersistentCache 正文（w07）未同步。
  3. @Volatile 缺失：Jellyfin S4 加过，Daoliyu / Subsonic / Navidrome 三家同模式未同步（w01）。
  4. XSS 转义：RemoteControlHtml 的 esc/escAttr 修复完整，BackupTransferServer 页面 backup-name 拼接未同步（w08，攻击面低）。
  5. 请求体上限：Backup / Playlist 上传有硬上限，RemoteControl / LocalInput 的 parseBody 全量进内存（w08）。
  6. 上传完整性：P2-11 已补 ModelTransfer 的 SHA-256，servePage 仍回显模型绝对路径（w08）。
  7. Locale 安全格式化：sha256Of 注释了 "%02x 受 Locale 影响" 并手写 hex，LrcParser.toLrcText 的 String.format(%02d) 未同步（w07）。
主题 B · 跨线程 / 一致性（5 条）
  1. SearchAggregator 源级超时形同虚设：withTimeoutOrNull 包阻塞 OkHttp execute，取消中断不了 socket 读，NAS 15s 实际受 Jellyfin readTimeout 120s 支配（w04；PlaybackService 的 resolve 同根因）。建议：per-call callTimeout 或 OkHttp suspend API，两处一起修。
  2. BaiduFileIndexCache.setCoverUrls 批量写未持 cacheLock——单条版注释明言「必须整锁」，批量版没有 → lost update + 同名 .tmp 互踩（w04）。
  3. NetworkMusicManager.unregisterService 清缓存 key 格式写错：拿歌曲 id 前缀匹配 source:id:quality 格式的缓存键，实际是 no-op（w04）。
  4. WeatherRadioManager 只取 NAS 第一页 500 首 + copy(id="nas_"+id) 篡改 id → 大曲库采样截断 + 统计口径分裂（w04）。
  5. AppPreferences 百度配置便捷写「读改写」无锁：token 刷新与开关切换并发丢字段（w07）。
主题 C · 协议 / 边界正确性（6 条）
  1. Jellyfin getStreamUrl 硬编码 stream.mp3，无损库被强制转码（w01，待确认是否有意）。
  2. Jellyfin scrobblePlay 语义错位：timestamp 当 PositionTicks、无播放完成上报（w01）。
  3. Jellyfin getYears 用 /Items/Filters，现行端点是 Filters2，404 则年代恒空（w01，待确认）。
  4. Navidrome / Subsonic getArtists 无图也返回封面 URL，与 Jellyfin 修复相反映，兜底链被跳过（w01）。
  5. Navidrome toggleFavorite 用本地缓存集定向，忽略入参 isCurrentlyFavorite，缓存陈旧时方向反（w01）。
  6. 崩溃恢复反推路径与命名规则不符（缺曲号前缀 / 档位后缀）→ 孤儿恢复大面积 miss；连带 reindexFromDisk 标题污染 dedupeKey（w02）。
主题 D · 安全 / 校验（3 条）
  1. 五个网络端点设置项无 URL 校验：用户输入 / 备份恢复的任意字符串直接成为请求端点，恶意备份可重定向搜索流量（w07）。建议：保存与恢复两路统一校验（scheme + host + 长度），非法回默认。
  2. ModelTransferServer 上传无总量上限（磁盘耗尽 DoS）+ 上传前先删真模型，失败丢 166MB 模型（w08）。
  3. 艺术家 / 专辑封面批量解析为串行阻塞链且无节流：MAX_CONCURRENT=5 实为回调批次大小；大曲库首刷分钟级且易触发第三方限流（w03）。

P1 · 明显功能异常

P1万花筒（E10）旋转矩阵写错，8 扇区全部塌陷
ddaef2d · visualizer/renderers/AdvancedRenderers.kt:57-80
现象：选中「万花筒」后画面不再是 8 瓣对称图形，而是从一个点朝各方向散射的"章鱼"状。100% 复现。
根因：把 withTransform{translate;rotate;scale} 手写成显式旋转时，线段两端用了两个不同的旋转角——内端用 rot（只有 rotation），外端用 base（k*45°+rotation）：
// 内端点：只转了 rotation，没有 k*45°
val px0 = cx + lx0 * rotCos - ly0 * rotSin
val py0 = cy + lx0 * rotSin + ly0 * rotCos
// 外端点：转了 k*45°+rotation
val px1 = cx + lx1 * baseCos - ly1 * baseSin
val py1 = cy + lx1 * baseSin + ly1 * baseCos
后果：8 个扇区的内端点全部落在同一个方向上，只有 k=0 那一瓣是对的。
修法：删掉 rot/rotCos/rotSin 三个变量，内外端统一用 baseCos/baseSin。
P1歌词点阵（E23）切歌后永远停在上一首的某句
1cda585 · renderers/LyricsDotMatrixRenderer.kt:70/145/400-433　+　ui/components/VisualizerStage.kt:107
现象：用「歌词点阵」时切歌，画面上的粒子文字不再变化，一直显示上一首停在的那一句；再次进入可视化才恢复。
根因：三重条件叠加——
  • VisualizerStage.kt:107 swapper = remember { RendererSwapper() } 无 key，切歌不会重建 renderer，也就不会走到 onEnter()（只有换主题才会）；
  • displayedLineIndex 只在 < 0 时初始化一次（:400），切歌后仍是上一首的行号（比如 12）；
  • 行切换只认 diff >= 1 且 phase == STEADY（:426）。新歌从 idx=0 开始 → diff = 0 - 12 = -12 → 永不触发。
附带：diff < 0（用户 seek 回上一句）同样没有处理分支。
修法：给 RenderContext 增加 songId / lyricsVersion，渲染器在 draw 里比对，变化即 displayedLineIndex = -1 并重采样（复用 onEnter 的重置块）；顺带补 diff < 0 的回退分支。
P1可视化封面取色用了无配置 ImageLoader —— 百度网盘源会 403
737ae0c · ui/viewmodel/VisualizerViewModel.kt:66
现象：百度网盘来源的歌曲，全屏可视化舞台的封面取色拿不到图，配色长期停留在 CoverPalette.Fallback。
根因：coil.ImageLoader(app) 每次新建一个全新无配置实例，绕过了 NasMusicApp.newImageLoader() 里注入的百度 dlink UA 拦截器（没有它直接 403）。
这是重复踩坑：MainViewModel.kt:2852-2855 已经因为同一个问题修过一次，注释写得清清楚楚——
// 取 Coil 全局 ImageLoader（与 PlaybackService/CoilBitmapLoader 同一实例）。
// 此前用 coil.ImageLoader(context) 工厂函数会创建全新无配置实例，
// 其 memoryCache/diskCache 与 UI 实际使用的缓存不是同一个，清除不生效。
val imageLoader = Coil.imageLoader(context)
附带：每次调用 new 一个 ImageLoader 且从不 shutdown()，泄漏线程池与缓存。
修法：改成 app.imageLoader（Coil 单例），与项目其余部分一致。

P2 · 体验与性能退化

P2Path 批处理把"逐元素 alpha"抹平了 —— 隧道/星芒丢了纵深感
ddaef2d · BasicRenderers.kt（TunnelRenderer / RadialBurstRenderer）
说明：合并成单条 Path 的前提是同色同 alpha。这两处不满足前提，属于"为降 draw 次数牺牲了视觉"：
  • 隧道穿越（E03）：原 alpha = fade * 0.7f，fade 是逐环的深度衰减 → 现在统一 0.7f，远处环不再淡出，纵深感消失；且新增了 BlendMode.Plus，重叠处会过曝。
  • 径向星芒（E06）：原 alpha = 0.6f + v * 0.4f（随频谱明暗）→ 统一 0.8f + BlendMode.Plus，端点不再随音乐呼吸。
对照：同批次的「烟花」背景频谱（alpha 恒 0.12）、「Bloom」辉光（逐层同 alpha）合并是安全的。
修法：按 alpha 分 2–3 档再分桶合并（同 E05 峰值帽按 hue 分桶的思路），或明确接受该取舍并更新效果预期文档。
P2频谱环峰值帽按 hue 分 4 桶 → 出现色阶断层
ddaef2d · BasicRenderers.kt:304-316
原本每根峰值帽用所在条自身的 hue（highlight），现在按 (t*4).toInt() 分 4 桶、用桶中心 hue 绘制，与所在条颜色最多差约 16.9°，能看到 4 段色阶。 代码注释仍写着"与所在条同色更亮"，与实现不符。
P2数字雨只剩 0 和 1 两个字符
ddaef2d · AdvancedRenderers.kt:499-501 / 586
digits = charArrayOf('0','1') + digitIdx = (…) % 2。原来是 0–9 随机，现在只有 0/1，"数字雨"变成"01 雨"。 CHANGELOG 只写了"2 数字 × 4 档绿"，没把这个视觉取舍讲清楚——如果是有意为之建议在 CHANGELOG 里明说，否则会被当成 bug 报回来。
另外 onExit() 只把 glyphs 置 null 未 recycle()（8 张小图，量小，低风险）。
P2播放控制行按钮高度不一致 + 宽度余量只剩 16dp
ddaef2d · PlayerControls.kt:378-383　vs　VocalToggleButton.kt:41
  • IconButton 紧凑尺寸 48dp → 40dp，但 VocalToggleButton 的 buttonSize 仍是 48dp 没同步 → 同一行里图标按钮 40dp 高、文字按钮 48dp 高，视觉不齐。
  • 按钮宽度全是硬编码魔数（幻 40 / K歌 52 / MTV 64），合计约 364dp，距 380dp 左栏只剩 16dp——再加一个入口就会溢出，正是这次 MTV 被截断的同一类问题。
建议：改用 weight 或按内容自适应，别继续堆魔数。
P2VisualizerStage 每帧重复计算歌词信息
ui/components/VisualizerStage.kt:225 / 260 / 376
  • computeLyricInfo() 每帧被调 2 次（当前层 + 交叉淡入的旧层），内部每帧 for (l in lines) 全量扫歌词求最长行（O(N)），并 new 一个 List。最长行/字数是歌曲级常量，不该每帧算。
  • :376 remember(lyrics, progressMs) { derivedStateOf { … } } —— key 里带了 progressMs，每帧变化导致 derivedStateOf 每帧重建，等于完全没缓存。
修法：歌词级常量提到 LaunchedEffect(lyrics) 算一次；remember 的 key 去掉 progressMs。
P2调试 println 遗留在采样热路径上
1cda585 · renderers/LyricsDotMatrixRenderer.kt:307-309
sampleLine() 里保留了诊断用的 println(...)，采样时逐次打印长字符串。既是日志噪音也是真实开销，删掉或改用 AppLog.d。
P2单测断言被明显放宽（1cda585）
app/src/test/.../player/SpectrumAnalyzerTest.kt:150-161
原本精确校验 assertEquals(expectedLinearBass, bass, 0.002)，现改为： 
assertTrue(actual in 0.2f..0.31f)
assertTrue(abs(actual - 0.2513f) < abs(actual - 0.3543f))
区间宽 0.11（注释仍称"≈0.25"），只判断"更接近线性分支而非 gamma 分支"，回归探测力大幅下降。 boost 语义改了确实要改断言，但建议收窄到 ±0.02，并保留对显示通道 gamma 契约的直接校验。
同批 BeatDetectorTest 把 MIN_BASS 由 0.12 降到 0.005（敏感度约 24 倍），建议确认安静段不会误触发鼓点。
